# CV site

A small, fast, static personal site. No framework, no runtime dependencies in production - just files served by [static-web-server](https://static-web-server.net/) in a hardened ~15MB container.

## Layout

```
.
├── public/              # what gets served
│   ├── index.html
│   ├── 404.html
│   ├── styles.css
│   ├── app.js
│   ├── assets/          # favicon, cv.pdf, manifest - hand-maintained
│   └── img/
│       ├── *.webp       # generated by `npm run build` from images-src/
│       ├── icons/       # hand-placed contact icons
│       └── tech/        # hand-placed tech badges (<slug>.webp)
├── images-src/          # drop card/hero originals here
├── tools/
│   ├── build-images.js  # images-src/*  ->  public/img/<name>.webp
│   └── clean.js         # remove generated public/img/*.webp
├── config.toml          # static-web-server config (headers, caching, CSP)
├── Dockerfile
├── docker-compose.yml
└── package.json
```

## Editing content

The work and project tiles are rendered from two arrays at the top of `public/app.js`:

```javascript
const JOBS = [
  {
    id: "vault",                              // used for the image: /img/vault.webp
    title: "Vault Platform",                  // card + modal heading
    meta: "Full Stack Developer · ...",       // subtitle
    blurb: "London, UK (Remote)",             // optional small line under meta
    description: "Vault Platform tackles ...",// modal body, keep it short
    link: "https://vaultplatform.com",        // omit to hide "Visit website"
    tech: ["node", "typescript", "react"],    // refs /img/tech/<slug>.webp
    // tile:    "other-image",   // optional: card image if not `id`
    // preview: "other-image",   // optional: modal image if not `id`
  },
  // ...
];

const PROJECTS = [ /* same shape */ ];
```

- **Add/change an entry:** edit the array.
- **Card vs modal image:** both default to `/img/<id>.webp`. Set `tile` and/or `preview` to use a different image for the card or the modal (e.g. a logo on the card, a screenshot in the modal).
- **Add a tech badge:** drop a WebP into `public/img/tech/<slug>.webp`.
- **Add a card image:** see below.

## Images

One WebP is generated per source, capped at 1000px wide (no upscaling). That's all the site uses - a single `<img src="/img/<name>.webp">`, no `srcset`, no format juggling.

To add or replace an image:

1. Drop the original (JPEG/PNG/WebP) into `images-src/`. The filename **without extension** is what you reference.
2. Run `npm run build`.
3. Reference it as `/img/<name>.webp` (or point a `tile`/`preview` field at it).

Logos with transparent backgrounds should be flattened onto a light background first - the cards sit on a dark surface, so a transparent dark logo would vanish.

Tweak `MAX_WIDTH` / quality in `tools/build-images.js` if needed.

## Quick start

```bash
# 1. Install dev dependencies (sharp, used only by the image build script)
npm install

# 2. Build the WebP images from images-src/
npm run build

# 3. Run locally with Docker
docker compose up -d --build

# Site is now at http://localhost:$PORT  (PORT is set in .env)
```

## Scripts

| Command | What it does |
|---|---|
| `npm run build` | Generate `public/img/<name>.webp` from `images-src/` |
| `npm run clean` | Remove generated `public/img/*.webp` (leaves `icons/`, `tech/`) |
| `npm run rebuild` | Clean then build |

## Compression

`static-web-server` compresses responses on the fly (`compression = true` in `config.toml`) - gzip/brotli negotiated per request. Nothing to pre-generate.

## Security posture

Container hardening (in `docker-compose.yml`):

- Runs as uid 65534 (nobody), not root
- Read-only root filesystem
- All Linux capabilities dropped (only `NET_BIND_SERVICE` re-added)
- `no-new-privileges` set
- Memory, CPU and PID limits set
- Log rotation enabled

To keep it off the LAN/internet and reachable only via your tunnel, bind the port to localhost - swap the `ports:` line in `docker-compose.yml` to `"127.0.0.1:$PORT:8080"`.

HTTP hardening (in `config.toml`):

- Strict `Content-Security-Policy` (self-only, no inline anything)
- `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`
- Hidden files ignored
- Sensible cache headers (HTML revalidates, static assets cached)

If you add inline `<style>` or `<script>` blocks, you'll need to loosen the CSP. Better to keep them in external files.

## Local development without Docker

```bash
python3 -m http.server 8080 --directory public
```

Fine for quick visual checks. It won't apply the SWS security headers or compression, so test in Docker before deploying.

## Deploying

Images are committed (`public/img/`), so the server needs nothing but Docker:

```bash
# locally, if images changed:
npm run build
git add -A && git commit && git push

# on the server:
git pull
docker compose up -d --build
```

The container binds to `$PORT` (see `.env`). Point your tunnel's upstream at it.
