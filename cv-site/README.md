# CV site

A small, fast, static personal site. No framework, no runtime dependencies in production - just files served by [static-web-server](https://static-web-server.net/) in a hardened ~15MB container.

## Layout

```
.
├── public/              # what gets served
│   ├── index.html
│   ├── 404.html
│   ├── styles.css
│   ├── app.js
│   ├── assets/          # favicon, cv.pdf, anything not generated
│   └── img/             # generated by `npm run images` (gitignored)
├── images-src/          # drop your originals here
├── tools/               # build scripts (not bundled into the container)
│   ├── build-images.js  # generate AVIF/WebP/JPEG variants
│   ├── compress.js      # pre-compress text assets (brotli + gzip)
│   └── clean.js         # remove generated files
├── sws.toml             # static-web-server config (headers, caching, CSP)
├── Dockerfile
├── docker-compose.yml
└── package.json
```

## Quick start

```bash
# 1. Install dev dependencies (sharp, used only by the image build script)
npm install

# 2. Drop your real images into images-src/ replacing the placeholders,
#    then build optimised variants and pre-compress text assets:
npm run build

# 3. Run locally with Docker
npm run docker:up

# Site is now at http://localhost:8080
```

## Scripts

| Command | What it does |
|---|---|
| `npm run images` | Generate AVIF/WebP/JPEG variants from `images-src/` into `public/img/` |
| `npm run compress` | Pre-compress HTML/CSS/JS/SVG with brotli + gzip |
| `npm run build` | Run `images` then `compress` |
| `npm run clean` | Remove generated files (`public/img/`, `*.br`, `*.gz`) |
| `npm run rebuild` | Clean then build |
| `npm run serve` | Quick local preview using Python's built-in server (no Docker) |
| `npm run docker:build` | Build the container image |
| `npm run docker:up` | Start in the background |
| `npm run docker:down` | Stop and remove |
| `npm run docker:logs` | Tail logs |
| `npm run docker:rebuild` | Rebuild and recreate the container |

## Images

The site uses `<picture>` elements with `srcset` to serve the smallest possible image for each viewport, in the best format the browser supports (AVIF → WebP → JPEG fallback).

To add or replace an image:

1. Drop the original (JPEG/PNG/WebP) into `images-src/`. The filename **without extension** is what you'll reference.
2. Run `npm run images`.
3. Reference it in HTML following the existing pattern in `index.html`:

   ```html
   <picture>
     <source type="image/avif"
             srcset="/img/myimage-400.avif 400w, /img/myimage-800.avif 800w"
             sizes="(max-width: 600px) 100vw, 400px">
     <source type="image/webp"
             srcset="/img/myimage-400.webp 400w, /img/myimage-800.webp 800w"
             sizes="(max-width: 600px) 100vw, 400px">
     <img src="/img/myimage-800.jpg" alt="..."
          width="800" height="500" loading="lazy" decoding="async">
   </picture>
   ```

Sizes generated: 400, 800, 1200 wide. Edit `SIZES` in `tools/build-images.js` to change. Sources smaller than a target width are skipped (no upscaling).

## Security posture

Container hardening (in `docker-compose.yml`):

- Runs as uid 65534 (nobody), not root
- Read-only root filesystem
- All Linux capabilities dropped (only `NET_BIND_SERVICE` re-added)
- `no-new-privileges` set
- Bound only to `127.0.0.1` - not reachable from the LAN or internet directly
- Memory, CPU and PID limits set
- Log rotation enabled

HTTP hardening (in `sws.toml`):

- Strict `Content-Security-Policy` (self-only, no inline anything)
- `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`
- Hidden files ignored
- Sensible cache headers (HTML revalidates, static assets cached for a year)

If you add inline `<style>` or `<script>` blocks, you'll need to loosen the CSP. Better to keep them in external files.

## Local development without Docker

`npm run serve` starts Python's built-in HTTP server on port 8080. Fine for quick visual checks. It won't apply the SWS security headers or pre-compression, so always test in Docker before deploying.

## Deploying

Build and run on your server:

```bash
git pull
npm install
npm run build
docker compose up -d --build
```

The container binds to `127.0.0.1:8080`. Point your ngrok tunnel's upstream at that.
